# Security reporting

Do not disclose exploitable vulnerabilities or credentials in public issues. Use GitHub's private vulnerability reporting on this repository through the Security tab. If it is unavailable, contact the maintainer privately through an established channel without posting the vulnerability publicly.

There are no supported production releases or guaranteed response times yet. Before live use, a supported-version policy and incident process must be established.

If a credential is exposed, revoke or rotate it immediately. Removing a file or rewriting history does not revoke the credential or remove copies already obtained. Public logs, issues, PRs and screenshots need the same review as source files.
